# 关键实现专题

## 1. Feed 与阅读链路

Feed 当前已经不是“列表 + 详情”的静态阅读器，而是一个带诊断状态的阅读工作台。

关键点：

- 详情支持深链接
- 条目支持已读、收藏、稍后读
- 正文支持自动补抓
- 摘要、翻译、正文三段都有状态字段
- 详情渲染已统一到正式 Markdown 组件
- 动态网页会在原生提取失败后自动回退到 Scrapling

当前最重要的实现语义：

- 如果正文缺失，不直接给固定兜底文案，而是进入 `enrich`
- 摘要会显式区分基于标题、片段还是正文
- 翻译会显式区分已完成、失败、跳过
- 抓取诊断会显式区分原生提取、Scrapling HTTP、Scrapling Dynamic、Scrapling Stealth

## 1.1 动态网页抓取与网页快照

网页正文和网页快照当前采用统一的分层策略：

1. 先走原生 HTML 提取
2. 命中已知动态域名或内容不足时回退到 Scrapling
3. `changedetection` 继续承担外部 diff 能力，不与 Scrapling 混成一层

这层的核心价值不是“多一个爬虫服务”，而是把原来静态抓不到的头条、脚本拼装页和部分公告页纳入可控链路。

## 2. Audio 与自动转写链路

Audio 当前的主路径已经是：

- `OSS + 远程批量 ASR`
- 长音频不再默认本地 realtime Paraformer

工作台能力包括：

- 上传文件
- URL 抓取
- 任务状态跟踪
- `概览 / 摘要 / 转写 / Markdown / 原始结果` 五个阅读 tab

自动转写当前真实参与执行的规则：

1. Source 级自动转写开关
2. 用户总开关
3. 每日自动次数上限
4. 单集时长与月预算限制

仍未完全收口的点：

- 时长未知时的前置预判

## 3. 日报与 AI 治理

日报已经升级成结构化多代理流水线，至少包含：

- 清洗
- 决策
- 研究
- 阅读导航

AI 管理中心已经统一治理：

- 模型库
- 提示词模板库
- 场景绑定
- 使用日志

日志当前已经支持：

- 来源区分：Hub / Audio
- 按状态、场景、Provider、关键字筛选
- 高频错误聚合
- 最近一次 30 天历史裁剪结果

## 4. Discovery 与 Folo 借鉴

当前已经借到的部分：

- 发现订阅的基础交互
- 诊断中心思路
- URL 状态同步

还值得继续借的部分：

- Discovery 排序与反馈
- 更高密度的阅读效率
- 设置页的信息架构组织

但边界很明确：

- 只借交互和 IA
- 不跟随 Folo 的深层架构
