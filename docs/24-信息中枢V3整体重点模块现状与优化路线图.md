# 信息中枢 V3 整体重点模块现状与优化路线图

## 1. 当前阶段判断

信息中枢 V3 现在不是“功能不够”，而是“能力很多，但主链路还不够可信、可读、可收口”。

从代码结构看，系统已经具备完整骨架：

- 输入层：`rss`、`webpage`、`webpage_index`、`rsshub`、`changedetection`、`youtube`、`BestBlogs`、邮箱、Dibao 对照侧车。
- 处理中台：去重、内容抽取、质量过滤、评分、摘要、翻译、Article Asset、来源健康、日报工作流。
- 输出层：Feed、Sources、日报工作台、日报阅读页、AI 用量、Reader Lab、导出、知识输出。

但从当前仓库状态看，项目仍处于明显的“大范围在制态”：

- 前端、后端、Docker、Nginx、QA、文档同时有大面积未提交变更。
- 说明方向已经在推进，但还没有完全收口成稳定产品。
- 当前最缺的不是新页面，而是统一的数据合同、阅读主路径和日报编辑层。

一句话判断：

**信息中枢 V3 现在最需要的，是从“系统控制台”收口成“可信阅读器 + 编辑型日报 + 可治理来源中心”。**

## 3. 当前最关键的问题，不是分散 bug，而是四个系统债

### 3.1 内容合同不统一

现在系统里同时存在：

- 全文可读
- RSS HTML 正文
- RSS 摘要
- 索引摘要
- 榜单摘要
- 网页快照
- 片段
- 标题

这些内容形态已经在后端被部分识别，但还没有完全变成前后端一致的数据合同。结果就是：

- 页面把线索当正文。
- 翻译按钮会因为“系统以为已经够了”而不触发。
- 摘要、改写、日报可能基于不同层生成，用户却看不出来。

### 3.2 阅读主路径还不够克制

Feed 三栏方向是对的，但详情页还没有真正做到“正文第一”：

- 顶部状态、提示、操作仍偏多。
- 主标签不够收敛。
- 诊断能力没有彻底后移。
- 结果是用户会先看到系统，而不是先看到文章。

### 3.3 日报还没有形成编辑中台

日报现在已经不是空壳，但也还不是正式产品：

- 结构页有了，内容厚度不稳定。
- `moduleNarratives` 已存在，但叙事仍容易机械拼接。
- `coverageItems`、重点文章、模块故事线之间还没有形成稳定分层。
- 页面能读，但不够像“高质量编辑型雷达”。

### 3.4 来源治理还没有完全反向控制阅读与日报

Sources 页已经有健康诊断和修复能力，但治理结果没有完全影响：

- Feed 推荐资格
- 正文补抓策略
- 翻译动作
- 日报候选权重

这会导致系统虽然“知道它有问题”，但主输出还继续吃这些问题数据。

## 4. 分模块问题盘点

### 4.1 来源采集与路由

强项：

- 多源能力完整，扩展性很强。
- 已经开始区分 `rss / webpage / webpage_index / curated_index / email`。

问题：

- 一些源名与实际域名错配，污染推荐和日报。
- `webpage` 与 `webpage_index` 语义边界仍在收口期。
- 不同源缺少稳定的 `feed_only / smart / full / disabled` 正文策略。

结论：

这个模块后面不要继续加新源优先，而是先把“来源真相”和“内容策略”固化。

### 4.2 正文可信层

强项：

- 已经引入 `readabilityStatus`、`contentEvidence`、原文补抓链路。

问题：

- 高价值长文源仍有回退到 RSS 原片段或噪音内容的情况。
- 原文结构保真度不够，代码、列表、表格、脚注仍不稳定。
- 某些索引类内容虽然已被正确识别，但还被放进阅读主流中。

结论：

这是当前整个项目最核心的 P0。正文层不稳，Feed、翻译、日报都会假稳定。

### 4.3 Feed 阅读台

强项：

- 三栏结构正确。
- 来源上下文、列表、详情已经可用。

问题：

- 顶部区域占比仍偏大。
- 摘要/原文/翻译之外的扩展能力没有完全退到次级层。
- 正文视觉中心不够强，仍像操作后台。

结论：

这里不是推翻重做，而是继续压缩高频噪音，把工具、诊断、扩展资产分层。

### 4.4 AI 阅读资产

强项：

- 已有 `article-assets`、问文章、翻译重跑、摘要等基础。

问题：

- 摘要、中文改写、问文章结果的边界和价值没有清晰区分。
- 资产生成后对 Feed 和日报的反哺还弱。
- “资产存在”还没有成为推荐和阅读的重要信号。

结论：

这一层应该升级成“读后资产层”，而不是几个散按钮。

### 4.5 日报雷达

强项：

- 已有异步生成、进度、日期导航、模块结构、阅读页。

问题：

- 仍偏系统融合，不够像编辑成稿。
- 模块叙事经常重复“发生了什么/为什么重要”模板句。
- 趋势、重点文章、更多动态、附录索引还没有稳定形成厚内容。

结论：

日报下一步重点不是再加卡片，而是增加 `editorialDigest` 中间层，把候选池变成真正可编辑素材层。

### 4.6 Sources 健康中心

强项：

- `SourceHealthSnapshot` 和五段诊断方向是对的。

问题：

- 还不够面向用户决策。
- “这个源应该保留、补抓、降权、改策略还是清退”还不够直接。

结论：

后面要把 Sources 做成主治理面，而不是“系统页”。

## 5. 后续优化计划

## Phase A：P0 可信底座收口

目标：让系统至少先做到“看见的内容是真的，动作是可解释的”。

1. 统一内容合同
   - 把 `全文 / RSS 正文 / 索引摘要 / 榜单摘要 / 网页快照 / 片段 / 标题` 彻底固化到 API。
   - 前端不再猜内容层。

2. 固化来源正文策略
   - 每个来源必须有明确 `feed_only / smart / full / disabled`。
   - `config_mismatch`、索引类、快照类进入强提示和降权。

3. 修正文抽取与保真
   - 优先吃干净 feed 内容。
   - 原站补抓只服务高价值条目。
   - 原文渲染保段落、列表、引用、代码、链接。

4. 统一翻译动作
   - 无全文但有 `originalUrl` 时，主动作必须是“补抓原文并翻译”。
   - 无动作不能静默。

验收标准：

- 抽测长文、索引、榜单、网页快照、中文短讯 5 类样本时，页面文案和实际内容层一致。

## Phase B：P1 阅读产品化

目标：让 Feed 变成愿意长期停留的阅读台。

1. Feed 首屏继续降噪
   - 主阅读只保留 `摘要 / 原文 / 翻译`。
   - 其余能力进入右侧抽屉或扩展栏。

2. 资产层收口
   - `改写 / 问文章 / 转写 / 知识 / 日报引用 / 人类反馈` 收进统一资产层。
   - 资产结果可保存、可回看、可反哺日报。

3. 正文样式对标 Dibao/QMReader/Folo
   - 正文宽度、字号、行高、图片、代码块都按阅读器处理。
   - 少按钮、少标签、少系统提醒。

验收标准：

- 10 条真实文章抽测中，默认视图不再被诊断和工具淹没。

## Phase C：P1/P2 日报产品化

目标：让日报从“生成页”变成“编辑型雷达”。

1. 增加日报编辑中间层
   - `editorialDigest`
   - `coverJudgement`
   - `radarOverview`
   - `moduleNarratives`
   - `moreDynamics`
   - `deepReads`
   - `coverageIndex`

2. 模块日报分层写作
   - 精选深写
   - 模块叙事
   - 更多动态
   - 深读
   - 附录索引

3. 让文章资产反哺日报
   - 重点文章优先引用 `key_points / evidence / actions`。
   - 减少重复复述原摘要。

验收标准：

- 单日报至少覆盖 35+ 条文章，且模块小节能读，不像机械拼接。

## 6. 现在不该优先做的事

1. 不继续盲目扩新信源。
2. 不再堆新页面解决旧问题。
3. 不先做复杂 embedding 推荐。
4. 不先做公共资产或团队协作扩展。

这些都不如先把“内容可信 + 阅读主路径 + 日报编辑层”做稳。

## 7. 最终建议

如果只保留一个后续执行顺序，应该是：

1. **来源真相与内容合同**
2. **正文保真与翻译动作**
3. **Feed 阅读降噪与资产分层**
4. **日报编辑中间层与模块长报**
5. **Sources 主治理面**
6. **外部源扩展与推荐深化**

也就是说，后面最正确的路线不是“哪里难看修哪里”，而是：

**先把内容层做真，再把阅读层做顺，再把日报层做深。**
