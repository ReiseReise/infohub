# 信息中枢 V3 文档总导航

这轮重构后的原则很简单：`docs/` 根目录只保留少数活跃主文档，所有历史过程材料统一进入 `docs/归档/`。

## 先看哪几份

| 文档 | 用途 |
|---|---|
| `01-顶层架构设计.md` | 看系统定位、五层架构、数据流、部署与模块边界 |
| `02-当前状态与功能地图.md` | 看当前做到哪、顶级设想对照总表、哪些能力该先做 |
| `03-路线图与优化计划.md` | 看下一步优先级、三层推进路线、Folo 借鉴边界 |
| `04-关键实现专题.md` | 看 Feed、Audio、日报、Discovery 等关键专题 |
| `05-运维与使用手册.md` | 看启动、迁移、排障、用户与管理员使用方式 |
| `06-质量门禁与测试规范.md` | 看回归标准、文档治理、归档规则 |
| `07-总览仪表板.html` | 用 HTML 快速看整体进度、流程和验收入口 |
| `08-AIHOT公开信源候选库.md` | 看从 AIHOT 公开页整理出的候选信源、分层、风险与导入前验收 |
| `source-registry/README.md` | 维护原始运行源、精简冷启动源和外部参考候选源；候选源默认关闭，由用户选择后导入 |
| `14-多剪藏入口CaptureInbox接入.md` | 看 Obsidian、Zotero、Organic Notes 等剪藏入口如何统一进入信息中枢与知识中枢 |
| `36-信息中枢V3可信可用收口任务跟踪.md` | 当前唯一执行真源；逐项查看状态、验收证据、阻塞和下一项任务 |
| `37-第三方参考与订阅源归属清单.md` | 看 QMReader、Follow Builders、AI HOT、Dibao 的来源归属、许可证边界和人工选择流程 |
| `38-信息中枢V3综合分析报告.md` | 看界面实测、架构、前端与产品的综合判断与三条根因归因；只做判断不跟踪执行 |
| `39-信息中枢V3优化设计与执行方案.md` | 看当前待采纳的优化条目池（P0/P1/P2）与需拍板的决策项；采纳后流转进 `36` |
| `40-Jev整体能力与应用学习介绍.md` | 学习 Jev 的能力、局限、应用与信息中枢旁路实验；第 12 节为体验升级点候选清单，均不代表已经接入生产 |
| `41-Jev体验升级点集成设计.md` | Jev 全场景旁路集成的使用入口、代码接入、接口、预算、隐私和验收；已实现并部署旁路版本，自动生效与质量验收仍未通过 |
| `30-信息中枢V3项目总控分析与优化计划.md` | 看当前项目总控判断、重点模块、运行态证据、问题归因与优化计划 |
| `28-信息中枢V3当前重点模块审计与优化计划.md` | 看上一版当前真实问题、8 个重点模块、结构债与执行顺序 |
| `归档/00-归档导航.md` | 看阶段、迭代、发布、评审等历史材料 |

## 阅读顺序

1. 新接手项目：先看 `01`、`02`
2. 想知道当前正在修什么、完成到哪：看 `36`
3. 想知道项目为什么按这个顺序修：看 `30`
4. 想知道长期路线：看 `03`
5. 要理解实现细节：看 `04`
6. 要启动、迁移、排障：看 `05`
7. 要执行回归与治理：看 `06`
8. 要维护或选择订阅源：看 `source-registry/README.md`
9. 想追历史过程：看 `归档/00-归档导航.md`

## 当前文档规则

1. 活跃文档全部放在 `docs/` 根目录。
2. 活跃文档全部使用中文命名。
3. 历史材料统一保留在 `docs/归档/`。
4. 不再保留旧目录壳的兼容跳转文件。
5. 当前执行进度只维护在 `36-信息中枢V3可信可用收口任务跟踪.md`；`30`、`28` 及其他审计计划只保留为背景材料。
5.1 `38` 只做判断与归因，`39` 只做条目池；两者都不维护执行进度。`39` 的条目被采纳后登记进 `36`，全部条目流转完毕后 `39` 整体归档，不出 v2。
6. 任务只有在代码、测试、真实页面和数据证据均通过后才能在 `36` 中勾选。
7. QA 基线仍以 `qa/reports/index.md` 为准，`docs/` 只负责说明与导航。
