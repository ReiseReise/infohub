# 信息中枢 V3 真实内容恢复记录

## 0. 本轮目标

本轮按“恢复真实可用内容优先”执行，不重置数据库、不删除历史内容、不新增外部信源，也不把信息中枢 V3 改成公共热点站。验收入口固定为 Docker 本地站 `http://localhost`，不再用临时 Vite 页面做用户验收。

目标是把用户看到的“Feed 空、日报空、无法继续加载”修成可解释、可加载、可复盘：

1. Docker 运行态使用最新源码。
2. 历史过滤错位数据回补到过滤池。
3. Feed 默认能看到主流程可见内容，并能通过按钮加载更多。
4. 日报没有高分内容时，降级使用最新可见内容，不再生成全段“暂无”的空壳。
5. 成长仪表盘和过滤池显示数据漏斗，避免用户误判系统没有抓取。

## 1. 根因确认

本轮排查确认问题不是单一前端样式问题，而是三层叠加：

- 运行态滞后：Docker 中 `hub-engine` 与 `nginx` 仍是旧镜像，用户实际看的不是最新本地修复。
- 历史字段错位：大量历史条目处于 `is_filtered=true && filter_bucket=main`，既不应该留在主 Feed，也不利于过滤池解释。
- 日报兜底不足：旧日报生成逻辑在 `topItems=[]` 时仍会生成结构完整但内容为空的日报，导致用户看到全段“暂无”。

## 2. 代码修复

### 2.1 日报兜底

`services/hub-engine/src/outputs/daily-report.ts` 新增 `selectDailyReportItems`：

- `scored`：存在高分可见条目时，按原有高分逻辑入报。
- `latest_visible`：有可见条目但分数不足时，降级取最新可见条目，保证日报有素材。
- `empty`：确实无可见条目时，才生成空日报诊断。

同时补充测试 `services/hub-engine/src/outputs/daily-report.test.ts`，覆盖“可见但低分时不输出空日报”的路径。

### 2.2 内容漏斗

`services/hub-engine/src/routes/items.ts` 的 `/api/items/stats` 返回统一漏斗：

- 库存总量
- 主 Feed 可见量
- 过滤池数量
- 历史错位数量
- 今日可见数量

`services/hub-engine/src/routes/insights.ts` 同步返回成长仪表盘窗口内的可见、过滤、错位、待分流数量。

### 2.3 Feed 与信源筛选

`apps/web/src/features/feed/page.tsx`：

- 顶部展示“可读 / 库存 / 过滤池”。
- 空状态改为诊断态，说明是账号无内容、筛选条件过窄、过滤过多，还是历史状态未回补。
- 来源筛选后展示该来源的总量、可读、过滤、未读，避免“有未读但列表加载不到”的错觉。
- “加载更多”保持为列表底部显式按钮，不依赖滚动触发。

### 2.4 成长仪表盘与过滤池

`apps/web/src/pages/Insights.tsx`：

- 生成日报后提示结果类型：高分日报、低分兜底日报、空日报诊断。
- 成长四轴为空时显示来源说明和过滤原因。

`apps/web/src/pages/Filtered.tsx`：

- 顶部从“当前池内 80”改为“过滤池总量”，并显示“已加载 x 条”。
- 列表底部增加“加载更多”，使用接口返回的 `total / hasMore / nextOffset`。
- 侧边栏 `Feed` 改为“信息流”，继续推进中文化。

## 8. 后续残留

1. AI 场景调用仍偶发 500 或输出过短，当前由确定性兜底保障日报可用，后续需要专项修模型配置和提示词输出格式。
2. Feed 中仍有一部分摘要质量差，例如“请提供待改写内容”这类模型失败文本，需要单独做摘要质量修复和重跑。
3. 信源等级仍大量停留在 B 质量策略，T1/T1.5/T2 的治理需要继续补元数据，不应在本轮为了好看硬改历史分级。
4. 过滤池加载更多已通，但右侧详情中的“条目 x / 当前已加载数”仍是当前页内序号，不是全局序号，这个属于体验优化，不影响主流程恢复。
