# 2026-03-03 Feed 音频联动闭环

## 1. 迭代目标

- 目标：补齐“Feed 条目 -> 一键播客转写 -> 状态回写 -> 音频详情查看”的可用闭环。
- 预期结果：用户无需切换上下文，在 Feed 中即可触发与追踪播客转写。

## 2. 变更摘要

### 2.1 hub-engine（触发 + 回写）

- 新增单条触发接口：`POST /api/items/:id/audio-transcribe`
  - 文件：`services/hub-engine/src/routes/items.ts`
  - 能力：从条目 `media_url/url` 触发 audio-service `from-url`，回写 `audioStatus/audioTaskId`
- 新增回调接口：`POST /api/hooks/audio-callback`
  - 文件：`services/hub-engine/src/routes/hooks.ts`
  - 能力：接收音频回调并写回 `audioStatus/transcript/knowledge/audioDuration`
  - 支持 `AUDIO_WEBHOOK_SECRET` 验签
- 新增服务调用封装：`services/hub-engine/src/services/audio.ts`

### 2.2 audio-service（失败回调补齐）

- `services/audio/app/api/tasks_from_url.py`
  - `article_id` 类型从 `Optional[int]` 调整为 `Optional[str]`（兼容 Feed UUID）
- `services/audio/app/tasks/audio_pipeline.py`
  - 失败路径新增 webhook 回调，确保 Feed 状态能落到 `failed`

### 2.3 前端（可操作可跳转）

- `apps/web/src/pages/Feed.tsx`
  - 详情页新增“播客转写”按钮
  - 展示音频状态标签（排队/处理中/已转写/失败）
  - 支持“查看音频任务”跳转到 `/audio?taskId=...`
- `apps/web/src/lib/api.ts`
  - 新增 `api.items.startAudio(id)` 调用
- `apps/web/src/pages/AudioStudio.tsx`
  - 支持通过 `taskId` 查询参数直接打开指定任务

## 4. 遗留问题

1. 自动转写策略（按规则/配额自动触发）尚未实现，当前为手动触发。
2. Nginx 统一入口仍未纳入默认 compose 启动链路。
3. X/公众号等非 RSS 信源仍未工程化接入。

## 5. 下一迭代建议

1. 在采集流水线中按 `auto_transcribe + quota` 规则自动触发音频任务。
2. 增加“回调失败重试队列”，提升跨服务稳定性。
3. 补充端到端回归用例：Feed 触发->音频完成->回写内容可读。
