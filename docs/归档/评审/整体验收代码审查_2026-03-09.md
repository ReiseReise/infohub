# 信息中枢 V3 整体验收 Code Review

## 范围

- 对照权威功能地图：`../../product/01-当前项目状态与能力地图.md`
- 抽查实现层：`hub-engine` / `audio-service` / `apps/web` / `nginx` / `qa`
- 补跑可直接执行的信号：
  - `services/hub-engine npm run build` 通过
  - `apps/web npm run build` 通过
  - `bash scripts/docs/check-docs.sh --strict` 通过
  - `bash qa/phase1/test_hub_engine.sh` 通过（21/21）
  - `docker compose ps` 显示核心容器 healthy

## Findings

### 1. Critical: 当前运行态仍在使用可预测的默认密钥与默认管理员口令，管理员面基本等于裸奔

- 代码和编排都允许在未显式配置时回退到默认值
- 运行中的容器里验证到弱默认值仍然生效

### 2. Critical: 两个“内部接口”被 Nginx 公开暴露，而且本身没有任何鉴权

- `/api/v1/tasks/from-url` 直接信任请求体 `user_id`
- `/api/internal/llm/complete` 无内部鉴权

### 3. Critical: 普通用户能读到管理员继承下来的 AI 配置明细

- 用户侧返回值直接带出敏感 AI 配置字段

### 4. High: 音频回调写入口默认不验签

- `AUDIO_WEBHOOK_SECRET` 为空时，公开写入口可被伪造

### 5. High: 知识库与 Obsidian 导出默认落到非持久目录

- 代码默认目录与 compose 挂载目录不一致

## 结论

这份 Code Review 的 5 个高风险项，已在 2026-03-09 到 2026-03-10 的后续修复中被作为首批阻塞项处理。  
该文档保留为“为什么那轮安全收口必须先做”的历史证据，不再承担当前状态解释职责。
