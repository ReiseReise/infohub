# 项目评审：数据新鲜度与 AI 治理

## Findings

### High

1. `README / 产品理解` 与运行模式存在天然认知偏差  
   当前项目采用本地手动启动模式。如果容器未运行，系统不会持续抓取；用户看到旧数据并不一定意味着采集器坏了。  
   本轮已补：启动后一轮 catch-up、新鲜度状态接口、Feed / Sources / Settings 提示。  
   后续要求：继续把“运行中 / 未运行 / 已过期 / 待补抓”作为一等状态维护。

2. `AI 管理中心` 此前难以回答“哪个功能正在用哪个模型”  
   原结构把场景绑定、模型接入、评分 Skills 混在一起，用户很难发现 Skills，也难理解模型和场景的关系。  
   本轮已补：`场景控制台 / 模型仓库 / 评分 Skills / 使用日志` 四分组，以及模型 `alias`。

### Medium

1. 日报默认提示词仍残留历史医疗 / PDAC 倾向  
   `apps/web/src/features/settings/page.tsx` 的 `DEFAULT_PROMPTS` 里仍有 PDAC 相关文案。  
   风险：管理员在未重新绑定模板时，可能误以为当前默认方向已经完全切回 AI / 头部舆论。  
   建议：把默认内联提示词彻底收口到 AI / 头部新闻主轴，避免与当前产品方向冲突。

2. 模型使用关系目前主要由前端聚合展示  
   现在 `usageScenes / usageCount` 主要基于前端读取 `ai_configs + scoring_skills` 后计算。  
   风险：跨服务调用或未来新增场景时，前端聚合可能漏掉真正的运行时使用关系。  
   建议：下一轮把 usage 聚合下沉成后端正式视图或接口。

## 本轮结论

- 数据旧的问题，核心先从“隐藏问题”变成“可见问题”了。
- AI 治理层的入口和信息架构已经明显更清楚，Skills 不再埋在深处。
- 仍需继续收口两件事：默认提示词方向统一、模型使用关系后端化。
