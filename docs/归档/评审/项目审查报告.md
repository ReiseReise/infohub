## 1. 关键问题总结（已修复）

### P0 — 根本原因：用户数据归属错误 ✅ 已修复

**问题描述**：所有 OPML 导入的订阅源和采集的条目均属于默认的 `admin` 用户（ID `00000000-0000-0000-0000-000000000001`），而实际登录的是 `reise@infohub.local`（ID `11ec2268-...`），导致 Feed 页面完全为空。

| 用户 | 修复前 sources | 修复前 items | 修复后 |
|------|------|------|------|
| admin (默认) | 557 | 19,158 | 0 |
| reise (实际) | ~1 | ~100 | 546 sources, 19,110 items |

**修复方法**：
```sql
UPDATE hub.sources SET user_id = '11ec2268-...' WHERE user_id = '00000000-...';
UPDATE hub.items   SET user_id = '11ec2268-...' WHERE user_id = '00000000-...';
UPDATE hub.ai_configs SET user_id = '11ec2268-...' WHERE user_id = '00000000-...';
UPDATE hub.insights   SET user_id = '11ec2268-...' WHERE user_id = '00000000-...';
```

同步修复 `cron.ts` 的 `DEFAULT_USER_ID` 指向 reise 用户，避免未来新采集数据再次归属到 admin。

### P0 — 垃圾数据：36kr feed-moment 抓取产生 title="1" 的无效条目 ✅ 已清理

**原因**：36kr 的 feed-moment RSS 格式特殊，仅有链接和 `<title>1</title>`，无正文。  
**修复**：删除 25 条 title="1" 且 content 为空的条目，同时删除 11 条重复源。

### P1 — 详情页"暂无可预览内容"无备用引导 ✅ 已修复

**原因**：部分 RSS 源只返回标题+链接，没有正文。  
**修复**：`Feed.tsx` 增加最小文本判断，无内容时显示原文链接。
