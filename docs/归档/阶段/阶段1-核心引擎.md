# Phase 1 归档：核心采集与处理引擎

## 1. 阶段目标与边界

- 目标：打通信源 CRUD、采集触发、条目查询核心 API。
- In Scope：`hub-engine` 基础路由、队列、采集流程。
- Out of Scope：AI 处理、知识检索、前端交互增强。

## 2. 输入上下文

- 依赖：Phase0 基础设施可用。
- 前置：PostgreSQL 和 Redis 健康。

## 3. 关键决策

| 决策 | 原因 | 结论 |
|---|---|---|
| 使用 Hono + TypeScript | 轻量、开发效率高 | `services/hub-engine` 采用 Hono |
| BullMQ 队列调度采集 | 降低采集峰值冲击 | 引入 fetch worker |

## 4. 实施清单

| 项目 | 状态 | 说明 |
|---|---|---|
| Sources API | ✅ | CRUD + 分类 + 统计 |
| Fetch API | ✅ | 单源触发 + 全量触发 + 队列状态 |
| Items API | ✅ | 列表、详情、标记、统计 |
| Phase1 QA | ✅ | 19 PASS / 0 FAIL / 1 SKIP |

## 5. 变更清单

- 代码：`services/hub-engine/src/{routes,scheduler,collectors}`
- 文档：`docs/phase1-hub-engine.md`
- 测试：`qa/phase1/test_hub_engine.sh`

## 6. 测试证据

- 命令：`bash qa/phase1/test_hub_engine.sh`
- 结果：19 PASS / 0 FAIL / 1 SKIP（采集内容受外网内容波动）

## 7. 风险与技术债

- 采集链路依赖外部源稳定性。
- 初始阶段缺少用户认证隔离（后续在 Stage C 完成）。

## 8. 回滚方案

1. 回退 `services/hub-engine/src/routes` 到上一稳定版本
2. 重启 hub-engine
3. 重跑 phase1 QA 验证
