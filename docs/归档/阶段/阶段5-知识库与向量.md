# Phase 5 归档：向量化 + 知识库检索

## 1. 阶段目标与边界

- 目标：实现知识条目增量拉取与全文/混合搜索能力。
- In Scope：embedding 处理器、knowledge 路由、pgvector 索引验证。
- Out of Scope：独立 RAG 服务编排。

## 2. 输入上下文

- 依赖：Phase2 的 AI 摘要数据与 Phase0 的 pgvector 扩展。
- 前置：items 表具备 embedding 列与向量索引。

## 3. 关键决策

| 决策 | 原因 | 结论 |
|---|---|---|
| 文本优先 + 向量增强的混合搜索 | 兼顾稳定性与语义召回 | `mode=text/hybrid` |
| embedding API 缺失时优雅降级 | 保障系统可用 | 向量失败回退文本搜索 |

## 4. 实施清单

| 项目 | 状态 | 说明 |
|---|---|---|
| embedding 处理器 | ✅ | `processors/embedder.ts` |
| knowledge API | ✅ | items/search/daily |
| Phase5 QA | ✅ | 13 PASS / 0 FAIL / 1 SKIP |

## 5. 变更清单

- 代码：`services/hub-engine/src/processors/embedder.ts`
- 路由：`services/hub-engine/src/routes/knowledge.ts`
- 文档：`docs/phase5-knowledge.md`

## 6. 测试证据

- 命令：`bash qa/phase5/test_knowledge.sh`
- 结果：13 PASS / 0 FAIL / 1 SKIP（无知识条目时跳过数量断言）

## 7. 风险与技术债

- 向量质量依赖模型和文本清洗质量。
- 混合检索策略后续需评估排序权重。

## 8. 回滚方案

1. 禁用向量流程（仅保留 text mode）
2. 回退 `embedder.ts` 与 `knowledge.ts`
3. 复测 phase5 QA
