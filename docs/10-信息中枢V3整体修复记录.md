# 信息中枢 V3 整体修复记录

## 0. 修复结论

本轮按 `09-信息中枢V3问题暴露报告.md` 的优先级推进，目标不是继续堆功能，而是把“抓取 -> 分流 -> 阅读 -> 反馈 -> 日报/成长沉淀”主流程修到可用、可解释、可验证。

已完成的主线：

1. 过滤路由字段统一：把 `isFiltered`、`filterBucket`、`qualityDecision` 收敛到同一段路由逻辑，避免内容从 Feed 和过滤池两边同时消失。
2. 日报空内容不再生成空壳：当今日有新增但无可入报内容时，生成“空日报诊断”，返回数据漏斗和过滤原因。
3. 成长仪表盘补充来源说明：成长轴使用统一主流程口径，并给出空状态原因、来源说明和站内详情入口。
4. Feed 降低主层级噪声：常驻信源栏改为来源筛选入口，列表内增加“加载更多”，反馈后展示画像状态。
5. 过滤池改为工作台滚动：桌面端左侧列表与右侧预览独立滚动，移动端保留自然纵向流。
6. 信源管理增加表格全览：支持表格/卡片切换，多选后可批量修改等级、类型、处理档位和启停状态。
7. 过滤策略补足生效证据：展示硬规则、AI 质检、人工反馈三类能力的启用状态和当前证据。
8. 页面中文化收敛：把主要用户可见的英文标题、工程词和按钮文案替换为中文；专有名词和技术缩写保留。

## 1. 后端数据闭环

### 1.1 统一过滤路由

新增 `services/hub-engine/src/lib/item-routing.ts`，把规则结果转换为统一路由状态：

- 通过规则：进入 `main`，`isFiltered=false`，`qualityDecision=pass`。
- 未通过但内容未就绪：留在 `main` 待复核，`qualityDecision=review`。
- 未通过且内容就绪：进入 `filtered`，`isFiltered=true`，`qualityDecision=filter`。

`services/hub-engine/src/processors/priority.ts` 已改为调用这段统一逻辑，避免不同处理入口各写一套过滤字段。

### 1.2 空日报诊断

新增 `services/hub-engine/src/outputs/daily-report-diagnostics.ts`，日报生成前会统计：

- 今日新增数量
- 可进入日报数量
- 已过滤数量
- 待复核数量
- 主要过滤原因

当“今日有新增，但可入报内容为 0”时，日报标题改为“信息中枢日报空结果诊断”，正文说明为什么为空，不再输出没有价值的空日报结构。

### 1.3 历史错位诊断脚本

新增 `services/hub-engine/src/scripts/diagnose-filter-routing.ts`：

- 默认 dry-run，只输出 `is_filtered=true && filter_bucket=main` 的错位数量。
- 加 `--apply` 后才会回补历史字段。
- 支持按用户范围诊断。

本轮没有默认修改历史数据库，符合“先诊断，再回补”的约束。

## 2. 日报与成长仪表盘

`services/hub-engine/src/routes/insights.ts` 已改为使用统一主流程口径：只把 `filterBucket=main && isFiltered=false` 的内容纳入成长仪表盘候选。

前端 `apps/web/src/pages/Insights.tsx` 已完成三项体验修复：

- “Growth Console” 改为“成长控制台”。
- 轴卡片展示空状态原因和来源说明。
- 条目主点击进入站内 Feed 详情，原文跳转降为二级动作。

这样用户看到空模块时，能区分“系统没数据”“被过滤掉”“该轴暂时没有命中内容”，而不是只看到空白。

## 3. Feed 主阅读流

`apps/web/src/features/feed/page.tsx` 已完成：

- 去掉常驻 `Source Rail` 主层级，改为顶部“来源筛选”入口。
- 列表底部增加贴近内容的“加载更多”按钮。
- 卡片保留标题、来源时间、摘要/理由和少量关键标签，降低工程指标的前台占比。
- 反馈提交后触发画像重算，并展示累计反馈、正向/负向数量、画像状态。
- 页面主要文案改为中文，如“阅读流”“信息流”“当前来源”“全部来源”。

浏览器验收时，当前验收账号的 Feed 可见条目数为 0，因此“某高未读信源连续加载超过 20 条”这一项没有足够数据做真实点击验证。代码路径已经实现并通过构建，后续需要用有未读数据的账号或先注入测试数据再做专项验收。

## 4. 过滤池

`apps/web/src/pages/Filtered.tsx` 已改为桌面工作台布局：

- 页面主体固定工作台高度。
- 左侧过滤列表独立滚动。
- 右侧预览独立滚动。
- 移动端仍保持自然纵向布局。

同时完成主要中文化：

- “Filtered Pool” 改为“过滤池”。
- “Decision” 改为“处理结论”。
- “Confidence” 改为“置信度”。
- “Risk Flags” 改为“风险标签”。
- “Case” 改为“条目”。

## 5. 信源管理

`apps/web/src/features/sources/page.tsx` 已新增表格全览模式：

- 可在“表格全览 / 卡片详情”之间切换。
- 表格列包含信源、类型、等级、权威、未读、精选率、重复率、健康、最近抓取和操作。
- 支持选择当前列表、取消选择。
- 支持批量改等级、批量改类型、批量改处理档位、批量暂停、批量启用。

信源分级已向 `T1/T1.5/T2` 兼容收敛，同时保留旧的 `S/A/B/C/D` 作为质量策略兼容项，避免历史数据直接断裂。

## 6. 过滤策略与反馈证据

`apps/web/src/pages/Rules.tsx` 已补充三类证据：

- 硬规则：展示启用规则数量。
- AI 质检：展示当前是否启用，避免用户误以为未启用能力已经在工作。
- 人工反馈：展示反馈数量和偏好画像状态。

页面也把“个人层”和“全局层”的含义拉开：

- 个人层强调“我的覆盖规则、我的反馈影响、我的偏好画像”。
- 全局层强调“系统默认规则、全局阈值、组织级过滤策略”。

## 7. 验证记录

已完成验证：

- `services/hub-engine`：`npm test` 通过，26 个测试全部通过。
- `services/hub-engine`：`npm run build` 通过。
- `apps/web`：`npm run build` 通过，仅保留 Vite chunk 体积提醒。
- 浏览器验收：`/feed`、`/insights`、`/sources`、`/rules`、`/filtered` 可打开；页面出现中文化后的核心入口；旧的 `Source Rail`、`Decision` 等用户可见文案未再出现；信源表格和批量控件可见；过滤池桌面工作台高度已生效。

未完全闭环的验证：

- Feed 高未读信源连续加载：当前验收账号可见 Feed 数据为 0，无法完成真实滚动加载验收。
- 历史数据回补：已提供 dry-run/可选 apply 脚本，但本轮未直接改历史库。
- 全量回归脚本：本轮优先完成单测、构建和页面级验收；若要上线前门禁，建议再跑轻量回归和前端端到端脚本。

## 8. 后续建议

第一优先级：用有真实未读数据的账号或注入测试数据，专项验收 Feed 加载更多、站内详情和反馈重算。

第二优先级：先运行历史错位诊断脚本 dry-run，确认影响范围后再决定是否 `--apply` 回补。

第三优先级：把日报空结果诊断接入前端“生成日报”按钮的可见反馈，避免用户只在后端记录里看到诊断。

第四优先级：补一个小型验收数据集，固定覆盖“主 Feed、过滤池、待复核、日报五桶、成长四轴、人工反馈”六条路径，后面每轮改 UI 都能快速验证。
