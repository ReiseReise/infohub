# 质量门禁与测试规范

## 1. 默认门禁

默认门禁是不连接隔离 QA 服务、不写运行数据的安全静态门禁，以下检查项都必须通过：

1. Hub Engine/Web/Audio 单元测试
2. Web ESLint（0 error，Fast Refresh/TanStack 兼容警告保留可见）
3. `services/hub-engine` 与 `apps/web` build
4. Portable 配置与 artifact 策略测试
5. full QA 入口关闭策略测试
6. 文档检查 `bash scripts/docs/check-docs.sh --strict`
7. `CHANGELOG.md` 与 `RELEASE_NOTES.md` 已同步

最小命令集：

```bash
make gate
```

会产生运行态副作用的 full suite 不属于默认 gate，而且当前**没有可证明完整隔离的 runner**。只设置 `QA_ISOLATED=1`、Hub URL 和 PostgreSQL 容器仍不足以隔离 RSSHub、Changedetection、ntfy、Audio、Redis 以及脚本中直接引用的热容器。

因此 `qa-verify`、`qa-full`、`gate-integration` 和 `run-regression.sh` 当前均在创建报告或调用子脚本前无条件拒绝执行。恢复这些入口前必须先交付完整的隔离依赖清单、所有服务 URL/容器参数化及其静态审计；不得把现有入口描述为可安全运行。

## 2. 推荐执行顺序

1. 基础设施与健康检查
2. Hub 核心 API 与鉴权
3. Feed / AI / 采集 / 音频相关回归
4. 前端构建与关键联动
5. 文档检查

## 3. QA 原则

1. 受保护接口必须有未鉴权断言
2. 新增关键流程必须有至少一条自动化回归
3. 默认 gate 不依赖外网真实平台稳定性
4. 如需外网烟测，放在独立入口

## 4. 文档治理规则

1. 活跃文档只保留在 `docs/` 根目录
2. 活跃文档统一中文命名
3. 历史材料统一放在 `docs/归档/`
4. 不保留旧路径兼容跳转文件
5. 当前任务、风险、验收证据与下一检查点的解释权归 `36-信息中枢V3可信可用收口任务跟踪.md`；`02` 只维护产品功能地图

### 4.1 证据生命周期（2026-07-26 采纳，D-4）

前两轮文档治理（`memory.md` 2026-03-10、2026-06 那轮）都只清存量、不改生成机制，结果都复发了。以下三条针对**生成端**：

1. **哪些任务需要独立验收文档**：只有跨服务改动、数据契约变更、发布级任务需要单独成文；局部改动的证据直接记在 `36` 号对应条目内，不另开文件。
2. **`qa/reports/` 保留期**：未被 `index.md` 引用的文件保留 30 天；近空日志（< 512 字节）与中间过程截图随时可清。索引过的报告长期保留。
3. **审计类文档上限**：同一时期只允许存在**一份**综合审计/优化文档。新的必须替换旧的并把旧的移入归档，不得并列累积——`21`、`23`–`32` 那 11 份同质文档就是没有这条规则的结果。

> 判据：清理动作前先问"它会不会自己长回来"。会，就说明该修的是生成端而不是存量。同样的道理也适用于数据——QA 僵尸账号在 2026-07-13 清理后十一天内重新累积 72 个，直到 `SEC-007` 堵住生成端才真正解决。

## 5. 归档规则

`docs/归档/` 当前固定保留五类材料：

- 阶段
- 迭代
- 发布
- 评审
- 模板

归档文件应保留 frontmatter，并确保时间、主题、阶段信息可追溯。

## 6. 通过标准

- 构建：0 error
- 回归：0 fail
- 文档：无缺失主文档、无缺失归档主目录、无旧路径残留的活跃引用

QA 最新执行基线仍以 `qa/reports/index.md` 为准。

### 可信研究新增验收边界

- 常规 `make gate`包含`src/research/*.test.ts`，检查引用、预算、网络边界和Fernet兼容；不调用付费模型。
- `qa/research/store.integration.mts`验证独立PostgreSQL中的并发幂等、过期执行权、取消后迟到写入、预算和不可变版本。
- `qa/research/pi-loop.integration.mts`使用明确合成响应驱动真实Pi SDK，验证研究、独立核对、稿件保存和追加指导的依赖关系；不计入内容盲选。
- `qa/research/api.integration.mts`通过隔离HTTP和BullMQ验证页面依赖接口；必须使用专用测试库及Redis，不能解禁旧full QA入口。
- `qa/research/compare.mts`只接受三个引擎齐全、模型及冻结材料一致的输出，建立人工盲选包。历史原稿与编码测试包不能冒充同模型实验。
- 内容上线门槛维持：至少20事件新稿获选率≥70%（平局不算获选）、5专题、无新增严重事实错误、修改时间与成本记录、连续3自然日实际使用。未收到人工选择不得勾选。
