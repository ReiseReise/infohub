# 质量门禁与测试规范

## 1. 默认门禁

以下检查项默认都必须通过：

1. `services/hub-engine` build
2. `apps/web` build
3. 全量回归 `bash scripts/qa/run-regression.sh --full --no-report`
4. 文档检查 `bash scripts/docs/check-docs.sh --strict`
5. `CHANGELOG.md` 与 `RELEASE_NOTES.md` 已同步

最小命令集：

```bash
make gate
```

## 2. 推荐执行顺序

1. 基础设施与健康检查
2. Hub 核心 API 与鉴权
3. Feed / AI / 采集 / 音频相关回归
4. 前端构建与关键联动
5. 文档检查

## 3. QA 原则

1. 受保护接口必须有未鉴权断言
2. 新增关键流程必须有至少一条自动化回归
3. 默认 gate 不依赖外网真实平台稳定性
4. 如需外网烟测，放在独立入口

## 4. 文档治理规则

1. 活跃文档只保留在 `docs/` 根目录
2. 活跃文档统一中文命名
3. 历史材料统一放在 `docs/归档/`
4. 不保留旧路径兼容跳转文件
5. 当前状态解释权归 `02-当前状态与功能地图.md`

## 5. 归档规则

`docs/归档/` 当前固定保留五类材料：

- 阶段
- 迭代
- 发布
- 评审
- 模板

归档文件应保留 frontmatter，并确保时间、主题、阶段信息可追溯。

## 6. 通过标准

- 构建：0 error
- 回归：0 fail
- 文档：无缺失主文档、无缺失归档主目录、无旧路径残留的活跃引用

QA 最新执行基线仍以 `qa/reports/index.md` 为准。
