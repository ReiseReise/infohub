# 信息中枢 V3 日报重新生成与处理链路修复记录

更新时间：2026-05-12

## 背景

用户反馈“点击重新生成日报后整体都没数据”，页面显示今日有新增内容，但日报生成口径中主流程可见、匹配范围、高分候选、最终入报均为 0。排查后确认问题不是单一前端展示，而是默认过滤规则、AI 评分失败兜底、历史路由字段和日报候选池口径共同导致。

## 根因

1. 默认全局规则 `AI高分优先` 被实现成硬过滤规则，低于 70 分的内容会进入过滤池；但业务语义应是“精选优先级”，不是“是否消失”。
2. `feed_scoring_skill` 空响应会被解析成默认 50 分，随后触发 70 分硬过滤，导致大量真实内容消失在主流程之外。
3. 存在多个重复激活的评分 Skill，同一类任务会重复执行，但失败结果仍可能落成空响应。
4. 日报候选池原本主要读取主流程可见内容，历史软分数误过滤内容无法参与日报重建。
5. 手动重新生成接口虽然新增了日期参数，但候选查询中 raw SQL 直接拼入 `Date`，导致接口 500。

## 已完成修复

### 过滤规则语义

- 将默认 `AI高分优先` 从 `ai_score_filter` 迁移为 `source_priority`。
- 保留 `minScore: 70` 和 `boost`，但只作为优先展示/精选加权，不再作为硬过滤。
- 服务启动时增加兼容迁移，自动把旧的全局 `AI高分优先` 规则迁移为软加权。
- 黑名单类规则仍保持硬过滤，避免把体育、汽车、游戏、足球等明确噪声恢复到主 Feed。

### 评分链路

- `parseSkillResponse('')` 不再回落到 50 分，而是抛出 `empty_scoring_skill_response`。
- 空评分响应会进入失败/复核链路，不再伪装成可靠低分。
- 新增 `dedupeActiveScoringSkills`，按 `presetKey/name` 对激活 Skill 去重，保留最近更新版本，避免重复激活。

### 历史数据回补

新增脚本：

```bash
node dist/scripts/repair-soft-score-filtered.js --email <email> --days 7
node dist/scripts/repair-soft-score-filtered.js --email <email> --days 7 --apply
```

脚本默认 dry-run，只统计不改库。apply 时只恢复 `filter_reason` 符合 `ai score too low: X < 70` 的软分数误过滤内容，修改路由字段为：

- `is_filtered=false`
- `filter_bucket=main`
- `quality_decision=review`
- `filter_reason=低分复核：原 AI 分数门槛不再作为硬过滤`
- `restored_from_filter=true`
- `restored_at=now()`

不会删除内容，不改原文，不恢复黑名单内容。

### 日报候选池

- 候选池从单纯主流程可见扩展为：主流程可见 + 软分数误过滤恢复候选 + 评分失败候选。
- `selectionMode` 新增 `review`，用于标记“低分复核”。
- 最终入报优先级改为：高分精选 → 低分复核 → 最新兜底 → 空诊断。
- 回补后的低分复核条目即使已经回到主 Feed，也会继续保留 `review` 语义，不会被误标成“最新兜底”。
- 日报生成口径增加：低分复核候选、软过滤恢复候选、评分失败候选。

### 前端交互

- 生成按钮明确为“重新生成当前日期日报”。
- 当前选中的日报档案日期会传给后端，不再默认只生成今天。
- 日报正文展示“高分精选 / 低分复核 / 最新兜底”来源标识。
- 日报工作流预览增加低分复核、软过滤恢复、评分失败漏斗。

## 剩余风险

1. 当前“低分复核”恢复后，日报不再空，但内容质量仍不稳定。36kr 的财经快讯、指数行情、泛商业公告会进入复核候选，说明日报范围和信源分层还需要继续收紧。
2. 评分失败内容已经可见化，但大量内容仍显示“评分失败/摘要失败”，下一步需要补 AI 处理失败重试与错误原因聚合。
3. 成长四象限目前主要集中到“认知升级”，其他轴仍依赖信源成长维度、AI 标签和标题关键词映射，需要进一步做映射规则。
4. 英文中文化门禁有效，但翻译失败会减少候选池；需要在工作流里提供“重试中文化”入口。

## 下一步建议

第一优先级是把“低分复核”进一步细分为“AI/科技相关复核”和“泛商业/财经噪声复核”，不要再让财经指数、普通股价和泛公告进入日报关键进展。第二优先级是为评分失败/摘要失败建立批量重试和错误归因面板，让系统从“恢复可见”进入“恢复高质量可读”。
