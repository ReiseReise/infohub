# 信息中枢 v3 现有融合精修说明 v0.6

## 为什么补 v0.6

v0.5 犯了一个方向错误：把参考阅读器图片当成了版式母版，导致侧边栏、页面心智和信息中枢现有功能脱节。v0.6 改为“现有页面融合精修”：保留当前 `Sidebar.tsx` 的导航结构和 `App.tsx` 的全路由，只吸收参考图里“文章/正文突出、次级信息弱化、大信息量靠滚动与折叠承载”的原则。

## 设计真源

- Figma 页面：`01 最新设计｜现有融合精修 v0.6`
- Figma 页面 URL：`https://www.figma.com/design/nFZbnEWt6FLIHTMSNvcPCj?node-id=57-2`
- 入口说明：`https://www.figma.com/design/nFZbnEWt6FLIHTMSNvcPCj?node-id=57-3`
- 本轮范围：桌面端全路由页面稿；移动端不恢复。

## 纠偏原则

- 侧边栏必须来自现有信息中枢：成长仪表板、日报、信息流、播客专栏、音频工坊、信源管理、网页监控、过滤策略、过滤池、导出、模型用量、阅读实验室、设置。
- 参考图只用于比例判断，不复制订阅分类、RSS 阅读器结构或示例内容。
- `/feed` 和 `/feed/:id` 保留现有 Feed 的列表、详情标签、证据、修复动作；只优化主次比例。
- 治理页继续以表格/队列为主，右侧 rail 只放选中对象上下文。
- 低频配置、日志、JSON、Prompt 链路和诊断默认折叠。

## 开发使用

开发时以 v0.6 为当前视觉与结构真源。v0.5 不再参考；v0.4 只保留“高密度控噪”的局部经验。

建议先实现：

1. `/feed` 与 `/feed/:id`：验证真实侧边栏、列表、正文、证据 rail 的融合比例。
2. `/sources`、`/monitor`、`/settings`：验证主表格 + 对象上下文。
3. 日报、报告、规则、媒体和阅读实验室页面：复用主队列/正文 + 右侧 rail + 折叠日志模式。
