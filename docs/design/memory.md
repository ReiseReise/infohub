# 设计记忆

- 设计真源：本轮以 Figma 文件 `nFZbnEWt6FLIHTMSNvcPCj` 为页面重设计真源。
- 设计方向：信息加工控制台，延续 `editorial reading desk + operator console`，不要做营销页或纯视觉炫技。
- Baseline 原则：先保留现有页面事实基线，再做优化稿；不要在 Baseline 上直接美化。
- 信息层级：优先呈现“今日判断、待处理队列、证据链、运行态”，减少单纯数据堆叠。
- 页面策略：不继续盲目新增页面，优先把现有功能通过全局 Shell、状态条、任务 rail 和诊断解释串起来。
- 本轮范围：当前开发参考只看桌面端；移动端从 Figma 当前结构移除，后续如要做需另开版本。
- 隐私边界：截图和文档只保留本地页面状态，不记录 token、密码和密钥。
- v0.2 决策：后续开发不按单页零散修样式，而按 7 个实现切片推进：Global Shell、Feed Workbench、Daily Production、Input Governance、Rules & Recovery、Governance Center、Media & Reader Lab。
- v0.2 决策：每个页面首屏必须先暴露判断、状态或待处理动作；低频配置、原始 JSON、长日志和高级参数默认下沉。
- v0.2 决策：v0.2 Figma 页只作为历史蓝图参考，v0.1 节点只作为历史方向参考。
- v0.3 决策：逐页实际页面稿 `01 最新设计｜桌面逐页重设计 v0.3` 是当前主设计真源；v0.2 只作为全局蓝图，不再直接指导页面实现。
- v0.3 决策：不要把 Baseline 的 UI 错误带入开发，尤其是 `/feed` 半屏空白、`/feed/:id` 证据链弱、`/insights` 重复列表挤占判断。
- v0.3 决策：开发优先顺序为 `/feed`、`/feed/:id`、`/insights`，再进入日报生产、输入治理、规则回收和治理中心。
- v0.3 清理决策：Figma 页面与页面稿统一中文命名，`99 归档｜当前版本截图基线` 只做旧版对照，不作为开发入口。
- v0.4 决策：当前主设计真源改为 `01 最新设计｜高密度精修 v0.4`；v0.3 降为结构归档参考。
- v0.4 决策：设计基底回到原版高信息密度页面，保留指标、列表、表格和真实内容样本，用 Tab、折叠、右侧 rail 和 chips 控噪，不再继续摘要化。
- v0.5 决策：当前主设计真源改为 `01 最新设计｜阅读优先全页面 v0.5`；v0.4 降为高密度控噪归档参考。
- v0.5 决策：阅读类页面以三栏阅读器比例为主，文章列表和正文/报告正文是主视觉；AI 总结、Ask AI、诊断、日志、高级配置只做弱化辅助层。

## 2026-07-26 字段诚实性判据（本轮新增）

前 6 版重设计与 7 次移动端修补都停在视觉层，页面却始终"没盖好"。根因是**页面的问题不在样式，在字段**。以下判据优先于任何视觉决策：

- **同名必须同义**。`funnel.finalCandidates`（漏斗预测）与 `report.itemCount`（报告实际保存）都叫"入报"，是口径矛盾的直接来源。任何数字都要能回答：属于哪个时钟（实时 / 快照）、处在哪一层、分母是谁。
- **假开关必须删**。判据是后端是否存在 `if (config.X === ...)` 行为分支；只有类型定义、默认值和归一化的配置项属于欺骗性 UI。`fallbackStrategy` 曾提供 5 个选项而系统行为完全不变。
- **默认视图必须信息最全**。用户不该为做"读/不读"的筛选决策而逐条点开详情。
- **内部处理状态不得混入内容字段**。`本地兜底`、`待补正文` 这类诊断标记进入 `aiTags` 后，会被当作内容主题展示给读者。
- **诊断必须有界面出口**。后端算出的健康状态与修复建议若无 UI 承载即等于不存在。2026-07-26 实测：评分模型熔断 8 天，后端一直在返回诊断与推荐修复模型，前端处理函数也写好了，但没有按钮绑定——日报因此长期无高分素材。**UI 重构裁剪功能时，"诊断与修复入口"优先级高于任何展示型面板。**
- **空数据是默认态而非边缘态**。当前抓取成功率 21%，未来多数日子就是空数据日。每个区块在 0 素材时只输出"事实 + 原因 + 唯一动作"，禁止与当日素材无关的断言（如"主线围绕 AI 产业展开"）。
- **Token 债务用增量护栏而非全局重刷**：新增代码使用语义 token，不为历史 2385 处 `zinc-*` 做一次性迁移——那正是前几轮烂尾的原因。
