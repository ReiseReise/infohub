# 信息中枢 V3 项目总审计与分阶段优化计划

## 1. 结论先行

信息中枢 V3 当前的真实状态，不是“功能不够”，而是**系统能力已经铺开，但内容可信层、阅读主路径和日报编辑层还没有完全收口**。

从仓库结构和最近真实验收看，项目已经具备完整产品骨架：

- 输入层：RSS、网页监控、网页索引、BestBlogs、邮箱、音频、Dibao 对照侧车。
- 处理中台：内容抽取、去重、质量过滤、评分、摘要、翻译、来源健康、日报工作流、Article Asset。
- 输出层：Feed、Sources、日报工作台、日报阅读页、AI 用量、Reader Lab、导出、知识输出。

但用户体验仍不稳定，主要不是因为“缺页面”，而是因为下面三个问题还没有被压成硬边界：

1. **内容层不够真**：全文、索引摘要、榜单摘要、网页快照、RSS 片段仍会进入同一阅读流。
2. **阅读层不够顺**：正文不是绝对主角，工具、诊断和状态仍然打断阅读。
3. **日报层不够深**：已经能生成，但还没有稳定形成“趋势 + 模块叙事 + 重点文章 + 全池覆盖”的编辑型雷达。

所以，下一阶段不应该继续“哪里不好看就修哪里”，而应该按一条主线推进：

**先把内容层做真，再把阅读层做顺，最后把日报层做深。**

## 3. 当前最关键的系统问题

## 3.1 内容合同还没有完全统一

现在系统里同时存在：

- 全文可读
- RSS HTML 正文
- RSS 摘要
- 索引摘要
- 榜单摘要
- 网页快照
- 片段
- 标题

这些类型后端已经开始识别，但还没有完全固化成前后端一致的数据合同。结果是：

- 页面有时把线索当正文。
- 翻译按钮会因为系统误判“内容已经够了”而不触发。
- 摘要、翻译、日报可能基于不同层生成，但用户看不出来。

## 3.2 Feed 还是更像控制台，不像阅读器

当前三栏方向是对的，但详情页还没有真正做到“正文第一”：

- 顶部提醒、状态、动作仍偏多。
- 主标签之外的扩展能力还在抢位置。
- 诊断和修复能力没有彻底后移。

用户先看见的是系统解释，不是文章。

## 3.3 日报还不是稳定的信息雷达

日报能力已经不少，但还没有形成正式产品气质：

- 能生成，但厚度不稳定。
- 有模块，但叙事仍容易机械拼接。
- 有重点文章，但覆盖还不够广。
- 有工作流，但候选池、重点文章、模块故事线之间没有稳定分层。

## 3.4 来源治理还没有完全前置

Sources 页已经知道很多问题，但治理结果没有完全影响：

- Feed 推荐资格
- 原文补抓策略
- 翻译动作
- 日报候选权重

这会导致系统“知道有问题”，但主输出仍持续吃问题数据。

## 3.5 历史数据债务明显

从已知审计结果看：

- `readability` 层只覆盖了少量条目。
- 很多高价值长文还停留在旧内容层。
- 旧 `webpage` 快照和新 `webpage_index` 单篇索引仍在并存。

这意味着即使代码已经修好，旧数据如果不补回，也会继续污染阅读和日报。

## 4. 模块级问题判断

## 4.1 来源治理与采集

这个模块是输入口。它现在最大的问题不是“抓不到”，而是“抓到了但分类不够准”。

重点风险：

- 官方名义源实际订阅社区 feed 或聚合 feed。
- `webpage` 快照、`webpage_index` 单篇索引、`curated_index` 榜单摘要在产品层没有被彻底分开。
- 缺少来源级 `feed_only / smart / full / monitor_only` 策略。

结论：后续不要优先继续扩新源，而要先把“来源真相”和“正文策略”固化。

## 4.2 正文可信层

这是当前最大 P0。

重点风险：

- `readabilityContent` 还没有成为原文 tab 的唯一可信底座。
- 原文格式保真还不稳定，代码、列表、表格、链接等样式仍会失真。
- 一些高价值 RSS 源其实 feed 内已给出完整正文，但没有被稳定优先使用。

结论：正文层不稳，Feed、翻译、日报都会假稳定。

## 4.3 Feed 阅读台

重点风险：

- 首屏信息密度过高。
- 正文视觉中心不够强。
- 资产、工具、诊断没有彻底分层。
- 用户无法低成本判断“这是一篇完整文章，还是一条线索摘要”。

结论：这里不是推翻重做，而是继续压缩高频噪音，强化正文优先级。

## 4.4 AI 阅读资产

重点风险：

- 摘要、中文改写、问文章、知识、转写等资产边界不清。
- 资产生成后没有真正进入阅读和日报复用。
- `item_reading_assets` 还没有成为高频数据层。

结论：这一层应该升级成“读后资产层”，而不是一组散按钮。

## 4.5 日报雷达

重点风险：

- 结构还偏“系统生成结果页”。
- 模块叙事和编辑判断厚度不足。
- 趋势、重点文章、更多动态、深读和附录索引还没有稳定共存。

结论：日报下一步重点不是继续堆卡片，而是增加编辑中间层，把候选池先变成可编辑素材层。

## 4.6 Sources 健康中心

重点风险：

- 还不够面向“保留/补抓/降权/清退”这种真实决策。
- 健康诊断还没完全前置到 Feed 和日报策略。

结论：后面要把 Sources 做成主治理面，而不是单独的系统页。

## 5. 优化计划

## Phase A：可信底座收口（P0）

目标：让系统先做到“看见的内容是真的，动作是可解释的”。

### 任务

1. 统一内容合同  
   固化 `全文 / RSS 正文 / 索引摘要 / 榜单摘要 / 网页快照 / 片段 / 标题` 到 API。

2. 固化来源正文策略  
   每个来源明确 `feed_only / smart / full / monitor_only`。

3. 修正文抽取与保真  
   优先吃干净 feed 内容；原站补抓只服务高价值条目；原文渲染保段落、列表、引用、代码、链接。

4. 统一翻译动作  
   无全文但有 `originalUrl` 时，动作必须是“补抓原文并翻译”；不能静默。

5. 补历史数据债  
   对高价值长文源跑一次正文回填和状态升级。

### 验收标准

- 抽测全文、索引、榜单、网页快照、中文短讯 5 类样本时，页面提示与实际内容层一致。
- Feed 原文 tab 不再把索引摘要或网页快照误当全文。

## Phase B：阅读产品化（P1）

目标：让 Feed 真正成为长期可用的阅读工作台。

### 任务

1. Feed 首屏继续降噪  
   主阅读只保留 `摘要 / 原文 / 翻译`；其余能力进入右侧抽屉或“更多工具”。

2. 资产层收口  
   `改写 / 问文章 / 转写 / 知识 / 日报引用 / 人类反馈` 收进统一资产层。

3. 正文视觉升级  
   按真正阅读器处理宽度、字号、行高、图片、代码块、列表。

4. 让资产反哺主阅读  
   文章资产可保存、可回看、可在日报重点文章里复用。

### 验收标准

- 10 条真实文章抽测中，默认视图不再被诊断和工具淹没。
- 用户能一眼分清“正文”“线索摘要”“榜单摘要”。

## Phase C：日报产品化（P1/P2）

目标：让日报从“生成页”变成“编辑型雷达”。

### 任务

1. 增加编辑中间层  
   引入 `editorialDigest / coverJudgement / radarOverview / moduleNarratives / moreDynamics / deepReads / coverageIndex`。

2. 模块分层写作  
   把日报拆成：封面判断、趋势总览、重点文章、模块日报、更多动态、深读、附录索引。

3. 让文章资产反哺日报  
   重点文章优先引用 `key_points / evidence / actions`，减少机械复述摘要。

4. 提升阅读页结构  
   目录 sticky、章节锚点、Markdown 视觉层级、右侧辅助导航都要稳定。

### 验收标准

- 单日报至少覆盖 35+ 条文章。
- 模块小节能读，不像机械拼接。
- 用户能通过日报快速回答：今天发生了什么、为什么重要、先读什么、后续看什么。

---

## 6. 现在不该优先做的事

1. 不继续盲目扩新信源。  
2. 不再用新页面掩盖旧内容问题。  
3. 不先做复杂 embedding 推荐。  
4. 不先做公共资产或多人协作扩展。  

这些都不如先把“内容可信 + 阅读主路径 + 日报编辑层”做稳。

---

## 7. 推荐执行顺序

如果只保留一条执行顺序，建议按下面推进：

1. **来源真相与内容合同**
2. **正文保真与翻译动作**
3. **Feed 阅读降噪与资产分层**
4. **日报编辑中间层与模块长报**
5. **Sources 主治理面**
6. **外部源扩展与推荐深化**

也就是说，接下来最正确的路线不是继续零散修补，而是：

**先把内容层做真，再把阅读层做顺，再把日报层做深。**
