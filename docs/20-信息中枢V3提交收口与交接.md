## 收口结论

本轮建议做 1 个完整收口提交，而不是强拆多个中间提交。

原因：

- 后端质量漏斗、批量 reprocess、日报候选收紧、Feed 详情诊断和 Insights 漏斗展示已经通过 API contract 相互依赖。
- 强拆为多个提交时，中间提交容易出现前端类型不完整或页面读取新字段但后端未返回的不可构建状态。
- 单提交可以保持验证证据完整，提交正文按模块列出变更，仍然可审。

明确不纳入：

- `memory.md`：既有未提交变更，不属于本轮信息中枢 V3 收口。
- `/private/tmp/*` 截图：作为验收证据路径记录，不进入仓库。
- `共享工作台/记忆集/recent.md`、`共享工作台/AIReise/*`：已按数字分身规则落盘，但不属于本项目 Git 提交。

## 已知剩余风险

1. 前端 bundle 超过 500KB，当前只是 Vite warning，后续可做路由级 code splitting。
2. RSSHub GitHub 外网路由在 Phase0 中返回 503，被记录为 skip；本地基础设施和核心采集链路未受影响。
3. Follow/Folo 私有 API 与登录态关注页默认自动抓取不在本轮范围；当前只保留 OPML/订阅包/公开 RSS 与 browser-assist 侧车方向。
4. 真实数据仍需要连续 3 天日报稳定观察，才能把“今天可信”升级为“日常完全可信”。

## 交接建议

提交后建议继续做两件事：

1. 连续 3 天跑真实日报一致性探针，记录 TOP、噪声排除、翻译失败和 Feed 详情解释是否稳定。
2. 下一轮只处理验收中暴露的高优先级问题，不再扩大范围；尤其不要在提交前引入新抓取渠道或大 UI 重做。
