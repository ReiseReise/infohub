# 运维与使用手册

## 1. 启动与健康检查

默认完整启动：

```bash
docker compose up -d --build
```

本地开发常用：

```bash
docker compose up -d postgres redis rsshub changedetection ntfy audio-service
cd services/hub-engine && npm run dev
cd apps/web && npm run dev
```

健康检查：

```bash
bash scripts/health-check.sh
curl http://localhost/health
curl http://localhost/api/health
curl http://localhost/api/audio/health
curl http://localhost:8010/health
```

## 2. 回归与验收

完整门禁：

```bash
make gate
```

真实音频烟测：

```bash
make qa-real-audio
```

准备验收账号：

```bash
make acceptance-users
```

## 3. 用户使用路径

### 3.1 阅读

- 在 `Feed` 浏览与筛选条目
- 打开详情查看摘要、正文、翻译、转写、知识内容
- 正文缺失时系统会自动补抓

### 3.2 信源

- 在 `Sources` 新增信源
- 支持 OPML 导入
- 音频类信源可开启自动转写
- 网页监控类来源可在 `Monitor` 里选择 `renderMode`

### 3.3 音频

- 在 `Audio` 上传文件或粘贴链接
- 在 `Podcast` 查看播客条目聚合
- 自动转写只对新抓到的音频条目生效

### 3.4 洞察与导出

- 在 `Insights` 生成日报
- 在导出能力中输出 Markdown / 知识库 / Obsidian 内容

## 4. 管理员常用路径

- 在 `Settings` 管理 AI 模型、模板、场景
- 查看 AI 使用日志与错误聚合
- 查看配额、诊断、历史裁剪、任务、用户、邀请码

### 4.1 AI 管理中心当前结构

1. `场景控制台`：看阅读评分、摘要、翻译、日报多代理分别绑定了哪套模型和模板
2. `模型仓库`：管理模型别名、真实目标、默认状态、测试状态和被哪些场景使用
3. `评分 Skills`：管理默认评分技能、草稿技能和偏好画像
4. `使用日志`：看调用趋势、热点、高频错误和单次事件

场景绑定只需要选择模型仓库里的模型别名。Provider、Base URL、豆包 endpoint、API Key 等详细字段只在 `模型仓库` 维护；保存场景时后端会从 `model_config_id` 自动派生运行字段。需要把阅读链路和日报链路统一切到豆包时，在 `场景控制台` 选择 `豆包-默认主模型` 后使用批量应用按钮。

新机器通过 Git 同步后，先在 `.env` 填好 `ARK_API_KEY` 与 `DEFAULT_LLM_ENDPOINT_ID=ep-...`，重启 `audio-service` 让模型仓库自动同步；如需把已有场景批量切到豆包，运行：

```bash
bash scripts/dev/apply-doubao-model-bindings.sh
```

## 5. 动态网页抓取诊断

- `Feed`：看单条内容的抓取引擎、渲染模式、阻断原因
- `Monitor`：看网页监控源的 `renderMode`、最近抓取引擎、变化摘要和阻断原因
- `Settings > 诊断中心`：看 `scrapling-service` 健康状态与最近一次 retention 结果

`renderMode` 推荐：

1. `auto`：默认，优先原生提取，必要时回退 Scrapling
2. `native`：静态站点优先，最低成本
3. `dynamic`：适合头条等脚本拼装页面
4. `stealth`：仅在动态模式仍容易被拦截时使用

## 6. 历史裁剪

- 默认保留最近 `30 天`
- `收藏`、`稍后读` 条目不自动删除
- 仍被保留条目引用的音频任务不会直接删除
- 删除老音频任务前会尽量清理底层存储对象；失败会记录在最近一次 retention 结果里

## 7. 数据新鲜度判断

- 当前默认是`本地手动启动`模式，不是常驻服务；如果容器没启动，数据不会自己更新
- 系统启动后会先补抓一轮到期来源，再进入每 5 分钟的混合调度
- 如果你看到旧数据，先看这三个入口：
  1. `Feed` 顶部的新鲜度提示和“立即补抓到期来源”
  2. `Sources` 每个信源的 `freshnessState / staleReason / nextFetchAt`
  3. `Settings > 诊断中心 > 抓取新鲜度`

## 8. 迁移、备份与回滚

备份：

```bash
bash scripts/backup.sh
```

本地快照 + OSS 归档：

```bash
make portable-backup
```

Mac 定时任务安装：

```bash
make install-launchd-backup
```

说明：

1. `HOST_DATA_ROOT`、`HOST_EXPORT_ROOT`、`HOST_BACKUP_ROOT` 控制宿主机目录
2. `data/pg`、`data/redis` 只做快照备份，不建议同步到云盘
3. `data/knowledge`、`exports/` 可按需同步到本地同步盘
4. 存在 `.env` 时必须设置 `PORTABLE_PASSPHRASE`；否则导出会在创建输出目录和调用 Docker 前拒绝执行
5. 只有显式 `--plain-env` 才允许单次明文导出；定时备份只在 `BACKUP_ALLOW_PLAINTEXT=true` 时传递该逃生口
6. `01-system` 只保存原始 `docker-compose.template.yml`；禁止生成 resolved Compose 或 config log，避免把环境变量展开到包内

可迁移包导出：

```bash
make portable-export
PORTABLE_PASSPHRASE='your-passphrase' make portable-export
```

恢复可迁移包：

```bash
make portable-import BUNDLE=./portable-bundles/<bundle>.tar.gz YES=1
```

### 8.1 当前恢复证据与口径

- 2026-07-13 已完成一份完整 portable 包的 SHA-256、客户端解密、tar 完整性以及独立 PostgreSQL + pgvector 恢复验证；详细数量和证据仍以 `docs/36-信息中枢V3可信可用收口任务跟踪.md` 的 `RESET-002` 为准。
- 这证明当前迁移包能够在隔离数据库中恢复，不证明百度网盘已经成为独立灾备。百度目标当前只标记为 `remote-declared`：供应商原生下载、新设备恢复、误删传播、回收站与版本保留仍未验证。
- 本节只固化恢复合同。本次治理不解密、不复制、不导入任何 1.1GB 数据包，也不触碰正在运行的数据库、容器和 `.env`。

### 8.2 最小恢复合同（不在生产目录演练）

**恢复对象**

- `01-system`：未展开环境变量的 `docker-compose.template.yml`、运行清单和必要文档；代码版本仍由项目 Git/当前工作树单独保护。
- `02-config`：默认加密配置模块；明文只是显式逃生口。密钥只从本机私有凭证位置取得，不进入文档、日志或同步目录。
- `03-data`：PostgreSQL dump，以及 `knowledge`、`audio-uploads`、`changedetection`、`ntfy`、`dibao` 等随包文件。

**前置依赖**

- 已明确选中的 bundle、对应 manifest/校验值、足够的本机临时空间、Docker/Compose、tar、OpenSSL，以及可用但不被打印的解密密钥。
- 必须使用隔离的恢复目录、独立 Compose project/容器名和非生产端口；不得把当前项目的 `data/`、`.env`、数据库或容器作为恢复试验目标。

**步骤**

1. 只读固定 bundle 名称、大小、manifest 和密文 SHA-256；任何一项缺失即停止。
2. 在 `local-data:I10/recovery-verification/<批次>/` 校验密文、解密并执行 tar 完整性检查；不在百度同步目录中解密。
3. 在隔离目标中恢复 PostgreSQL，并验证 pgvector 扩展、关键 schema 与 manifest/证据中登记的行数；随后核对随包文件的存在性和可读性。
4. 只在隔离恢复全部通过后检查服务启动与健康入口；禁止启用生产抓取、调度、通知或外发。
5. 把测试时间、bundle 指纹、恢复范围、成功证据和未覆盖边界写回 36 号执行真源；测试目录的清理另开确认任务。

**成功证据**

- 密文 SHA-256、解密和 tar 完整性均通过。
- PostgreSQL 能在隔离实例中导入，pgvector 与关键 schema 可用，关键行数符合当次 manifest/恢复记录。
- 随包文件存在且可读取；隔离服务健康检查通过；生产项目、生产数据和正式调度没有发生变化。

**停止条件与未验证边界**

- 密钥缺失、校验不一致、tar 损坏、空间不足、目标不隔离、容器名/端口与生产冲突或当前工作树无法保全时立即停止。
- 当前 `scripts/portable/import-bundle.sh` 会先处理并可能覆盖 `.env`，之后才检查 data 恢复所需的 `--yes`。在确认门移到所有写入之前，缺少 `YES=1` 不能被当作 dry-run，也不得在活跃项目根运行该入口。
- 当前合同没有验证供应商原生远端取回、新设备恢复、密钥丢失、远端删除/版本保留以及最新运行数据的恢复点目标。

回滚与排障的原则：

1. 先保数据，再动容器
2. 先看统一入口健康检查，再看单服务日志
3. 破坏性重建只在明确接受数据卷重建时执行

## 9. 常见问题

1. 抓取无数据：先看服务是否在运行，再看新鲜度状态、信源配置、抓取队列与最近抓取结果
2. 动态网页抓不到：先看是否命中了 Scrapling，若仍失败再调整 `renderMode`
3. 自动转写没触发：检查源级开关、用户开关、每日上限、时长/预算限制
4. 豆包不生效：优先检查 `ARK_API_KEY` 和 `DEFAULT_LLM_ENDPOINT_ID`，再到 `模型仓库` 测试 `豆包-默认主模型`
5. 原文/翻译缺失：先看条目状态，不要只看空白内容

### 可信日报与专题研究：实验引擎

本轮新执行链位于 `services/hub-engine/src/research/`，使用TypeScript、BullMQ、Pi Agent Core 0.85.1及现有PostgreSQL。Node要求至少22.19。它不加载编码Agent的Shell、文件工具、个人扩展或Skills。当前默认日报仍为旧引擎，发布状态以36号文件为准。

**启用前条件**：完成数据库逻辑快照及独立实例实际恢复；在隔离库验证 `scripts/research/001-trusted-research.sql` 后，再将同一增量迁移用于目标库。迁移仅新增研究表、索引及不可变快照约束；不删除旧原文、旧日报，也不自动执行大规模回填。应用不会启动时自行迁移数据库。

**配置**：`TRUSTED_RESEARCH_ENABLED=true`同时启用研究API写操作和研究Worker；缺省false。DeepSeek优先读取现有模型仓库中provider=`deepseek`、model_name=`deepseek-flash`的活跃LLM配置，沿用Fernet加密（显式ENCRYPTION_KEY，或与现有Audio一致的JWT_SECRET派生密钥）。也支持私有环境变量`DEEPSEEK_API_KEY`。研究模型只访问官方DeepSeek地址，不修改其他业务场景绑定。

联网需配置`BRAVE_SEARCH_API_KEY`与`BRAVE_SEARCH_COST_MICROS`（每请求费用，单位百万分之一元；缺失价格时拒绝调用）。公开搜索词必须来自任务明确允许外发的词表。网页正文在应用端做协议、地址、重定向、响应大小和超时限制，解析结果存入原文版本表。

每份成果预算为10,000,000微元（10元），恢复、指导与局部重跑共用。模型调用采用已记录的保守人民币费用估算，不冒充供应商实扣；首版价格快照有效至2026-09-21，过期明确暂停，核对官方价格后更新。研究阶段为最终核对/编辑预留1.5元。没有用量或调用中断的费用保留预留额，不能当零费用继续放行。

**接口**：保留原日报接口；显式提交`engine=trusted`选择实验引擎。研究记录使用`/api/research/runs`及详情、events、cancel、guidance、resume、drafts接口。写入任务和指导要求`Idempotency-Key`；同键不同输入返回冲突。同步旧调用行为保持不变，实验引擎当前返回202和持久任务查询地址。`/api/daily/reports/latest?engine=trusted`读取实验稿；当前始终标为待验收稿，不自动外发。

研究模块重跑必须指定runId和事件stepId；final/decision/reading只重跑整报编辑及核对。cleaning映射为冻结选材复核，返回事件/原文数量、缺失证据及enqueued=false；不触发模型或重跑事件。相同Idempotency-Key复用复核结果，默认按任务revision去重；新增或更换材料需新建任务。完整日报的真实内容与浏览器验收仍待完成。

**恢复与人工修改**：取消落库并撤销执行权，迟到模型结果不可写稿；费用仍按真实返回记录。过期Worker执行权可回收，恢复保留已完成阶段及费用。完成后追加指导建立新研究阶段，保留旧稿；人工稿优先显示，模型新稿不会静默替换人工稿。编辑使用baseVersion防止并发覆盖。

**回退**：生产默认引擎尚未切换。关闭研究开关会停止新增执行；研究表和原文/稿件版本保留，不执行反向删表。回退代码前先停研究Worker，保存进行中任务及费用状态。数据库整库恢复只用于确认的数据损坏，不能用于普通代码回退，以免抹掉后续抓取。

**隔离验收**：`qa/research/README.md`记录专用PostgreSQL、Redis和启动方式；`server.mts`不启动生产抓取/日报调度。合成模型的通过记录不代表DeepSeek真实内容或生产上线通过。

2026-09-14研究增量迁移已应用生产（详见36号文件）。经实际恢复验证的私有快照及说明位于 `local-data:I10/staging/trusted-research-production-20260914/`。这是同盘回退副本，不是独立灾备。新研究Hub/Web已于2026-09-14部署试用，研究Worker已启用；默认日报引擎仍为旧版。
