# 运维与使用手册

## 1. 启动与健康检查

默认完整启动：

```bash
docker compose up -d --build
```

本地开发常用：

```bash
docker compose up -d postgres redis rsshub changedetection ntfy audio-service
cd services/hub-engine && npm run dev
cd apps/web && npm run dev
```

健康检查：

```bash
bash scripts/health-check.sh
curl http://localhost/health
curl http://localhost/api/health
curl http://localhost/api/audio/health
curl http://localhost:8010/health
```

## 2. 回归与验收

完整门禁：

```bash
make gate
```

真实音频烟测：

```bash
make qa-real-audio
```

准备验收账号：

```bash
make acceptance-users
```

## 3. 用户使用路径

### 3.1 阅读

- 在 `Feed` 浏览与筛选条目
- 打开详情查看摘要、正文、翻译、转写、知识内容
- 正文缺失时系统会自动补抓

### 3.2 信源

- 在 `Sources` 新增信源
- 支持 OPML 导入
- 音频类信源可开启自动转写
- 网页监控类来源可在 `Monitor` 里选择 `renderMode`

### 3.3 音频

- 在 `Audio` 上传文件或粘贴链接
- 在 `Podcast` 查看播客条目聚合
- 自动转写只对新抓到的音频条目生效

### 3.4 洞察与导出

- 在 `Insights` 生成日报
- 在导出能力中输出 Markdown / 知识库 / Obsidian 内容

## 4. 管理员常用路径

- 在 `Settings` 管理 AI 模型、模板、场景
- 查看 AI 使用日志与错误聚合
- 查看配额、诊断、历史裁剪、任务、用户、邀请码

### 4.1 AI 管理中心当前结构

1. `场景控制台`：看阅读评分、摘要、翻译、日报多代理分别绑定了哪套模型和模板
2. `模型仓库`：管理模型别名、真实目标、默认状态、测试状态和被哪些场景使用
3. `评分 Skills`：管理默认评分技能、草稿技能和偏好画像
4. `使用日志`：看调用趋势、热点、高频错误和单次事件

场景绑定只需要选择模型仓库里的模型别名。Provider、Base URL、豆包 endpoint、API Key 等详细字段只在 `模型仓库` 维护；保存场景时后端会从 `model_config_id` 自动派生运行字段。需要把阅读链路和日报链路统一切到豆包时，在 `场景控制台` 选择 `豆包-默认主模型` 后使用批量应用按钮。

新机器通过 Git 同步后，先在 `.env` 填好 `ARK_API_KEY` 与 `DEFAULT_LLM_ENDPOINT_ID=ep-...`，重启 `audio-service` 让模型仓库自动同步；如需把已有场景批量切到豆包，运行：

```bash
bash scripts/dev/apply-doubao-model-bindings.sh
```

## 5. 动态网页抓取诊断

- `Feed`：看单条内容的抓取引擎、渲染模式、阻断原因
- `Monitor`：看网页监控源的 `renderMode`、最近抓取引擎、变化摘要和阻断原因
- `Settings > 诊断中心`：看 `scrapling-service` 健康状态与最近一次 retention 结果

`renderMode` 推荐：

1. `auto`：默认，优先原生提取，必要时回退 Scrapling
2. `native`：静态站点优先，最低成本
3. `dynamic`：适合头条等脚本拼装页面
4. `stealth`：仅在动态模式仍容易被拦截时使用

## 6. 历史裁剪

- 默认保留最近 `30 天`
- `收藏`、`稍后读` 条目不自动删除
- 仍被保留条目引用的音频任务不会直接删除
- 删除老音频任务前会尽量清理底层存储对象；失败会记录在最近一次 retention 结果里

## 7. 数据新鲜度判断

- 当前默认是`本地手动启动`模式，不是常驻服务；如果容器没启动，数据不会自己更新
- 系统启动后会先补抓一轮到期来源，再进入每 5 分钟的混合调度
- 如果你看到旧数据，先看这三个入口：
  1. `Feed` 顶部的新鲜度提示和“立即补抓到期来源”
  2. `Sources` 每个信源的 `freshnessState / staleReason / nextFetchAt`
  3. `Settings > 诊断中心 > 抓取新鲜度`

## 8. 迁移、备份与回滚

备份：

```bash
bash scripts/backup.sh
```

本地快照 + OSS 归档：

```bash
make portable-backup
```

Mac 定时任务安装：

```bash
make install-launchd-backup
```

说明：

1. `HOST_DATA_ROOT`、`HOST_EXPORT_ROOT`、`HOST_BACKUP_ROOT` 控制宿主机目录
2. `data/pg`、`data/redis` 只做快照备份，不建议同步到云盘
3. `data/knowledge`、`exports/` 可按需同步到本地同步盘
4. 若不希望明文打包 `.env`，请设置 `PORTABLE_PASSPHRASE`

可迁移包导出：

```bash
make portable-export
```

恢复可迁移包：

```bash
make portable-import BUNDLE=./portable-bundles/<bundle>.tar.gz YES=1
```

回滚与排障的原则：

1. 先保数据，再动容器
2. 先看统一入口健康检查，再看单服务日志
3. 破坏性重建只在明确接受数据卷重建时执行

## 9. 常见问题

1. 抓取无数据：先看服务是否在运行，再看新鲜度状态、信源配置、抓取队列与最近抓取结果
2. 动态网页抓不到：先看是否命中了 Scrapling，若仍失败再调整 `renderMode`
3. 自动转写没触发：检查源级开关、用户开关、每日上限、时长/预算限制
4. 豆包不生效：优先检查 `ARK_API_KEY` 和 `DEFAULT_LLM_ENDPOINT_ID`，再到 `模型仓库` 测试 `豆包-默认主模型`
5. 原文/翻译缺失：先看条目状态，不要只看空白内容
