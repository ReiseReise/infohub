## 0. 背景

### 0.1 为什么再写一份

`docs/21-29` 已有 9 份"整体模块分析与优化计划"类文档，但前端体验层未真正落地。本次诊断后不再写第 10 份诊断文档，而是直接转化为 6 个 Phase 任务，关键是要**真正动手执行**。

### 0.2 核心诊断（精炼版）

| 问题 | 根因 |
|---|---|
| 日报太乱 | 日报本质是 AI 生成的 Markdown 长文，靠 `MarkdownContent` 渲染，无结构化字段、无视觉分层；工作台首页信息密度爆炸（4 KPI + 工作流 + Agent 矩阵 + 预览 + 监控 + 建议全在一屏） |
| RSS 信息流展示问题多 | `Feed page.tsx` **2404 行**单个"上帝组件"，**30+ useState**，装了 `@tanstack/react-query` 但完全没用；无 shadcn/radix/headlessui，所有交互组件手搓；默认入口是 `/insights` 而非 `/feed` |
| 配置页面干扰多 | `Settings page.tsx` **3374 行**，7 主 tab + 4 admin tab + 4 AI center tab = 15 个子区域全揉在一起；侧边栏 13 个一级导航项无分组平铺 |
| 整体设计/技术问题 | `index.css` 只有一行 `@import "tailwindcss"`，无 Design Token；zinc/teal/emerald/amber/violet/rose 配色乱用；无组件库；pages/ 和 features/ 并存混乱；无虚拟列表；移动端仅靠 Tailwind 断点 |

### 0.3 与参考站点的差距

| 参考站点 | 优秀做法 | 当前差距 |
|---|---|---|
| **AI HOT**（aihot.virxact.com） | 单列高密度文本流，每条 8+ 字段（时间/来源/热度分/标题/摘要/标签/多信源/推荐理由），客观摘要与主观推荐用 `* * *` 分隔 | 当前 Feed 完全没有"客观/主观分离"和"多信源聚合"的视觉呈现 |
| **AINews**（news.smol.ai） | 编辑增强型 Issue，每期有"编辑短评 + 数据来源声明 + 主题板块（粗体摘要句+引用+数据点）+ Top tweets + Reddit 分组"固定结构 | 当前日报只是 Markdown 长文，没有 Issue 化、没有结构化字段 |
| **QMReader**（rss.qiaomu.ai） | 深度阅读 + 公开资产沉淀（中译/重写/划线/点评/对话） | 当前 Feed 有 7 个 tab 但没有资产沉淀机制 |
| **Folo** | Discovery 排序与反馈、重度阅读效率、Settings/Feed 信息架构 | 路线图（docs/03）已明确借鉴方向但未落地 |
| **Follow Builders**（github） | 来源清单参考 | 已通过候选源目录（254 条）吸收 |

## 1. Phase A: 信息架构重构（P0）

**目标**：解决"干扰信息多"的根因——所有功能平铺、职责边界模糊。

**预估工作量**：1-2 周

**依赖**：无（可与 Phase B 并行）

### 子任务

- [ ] **A1** 侧边栏导航分组重构：消费区（信息流/日报/播客专栏）/ 治理区（信源/监控/过滤策略/过滤池）/ 工具区（音频工坊/导出/阅读实验室）/ 后台（设置/模型用量）。每组不超过 4 项，组间有视觉分隔
- [ ] **A2** 默认入口从 `/insights` 改为 `/feed`，符合信息流产品惯例。`App.tsx` 中 `<Route path="/" element={<Navigate to="/insights" replace />} />` 改为 `/feed`
- [ ] **A3** Settings 拆分：用户偏好（通用/阅读 AI/集成/播客配额）保留在 `/settings`；管理后台（AI 中心/诊断中心/用户管理/邀请码/系统任务）独立到 `/admin`，权限校验单独处理
- [ ] **A4** 日报工作台（`/daily/workbench`）和日报阅读页（`/daily/reports/latest`）职责彻底分离：工作台只负责"运行/观测/配置"，阅读页只负责"读"，移除阅读页里的"运行漏斗/制作信息"诊断内容（移到工作台的诊断 tab）

### 验收标准

- 侧边栏 13 项分 4 组，每组不超过 4 项
- `/settings` 不再包含管理员专属内容
- 日报阅读页右侧 sticky 边栏只剩"目录 + 跳转 + 元信息"
- 默认登录后跳 `/feed` 而非 `/insights`

### 对照参考

Folo 的 Settings/Feed 信息架构组织（路线图已明确借鉴方向但未落地）

## 2. Phase B: 设计系统与组件库（P0）

**目标**：解决"没有设计系统、配色乱用、组件手搓"的根因。这是后续所有视觉优化的基础。

**预估工作量**：2-3 周

**依赖**：无（可与 Phase A 并行）

### 子任务

- [ ] **B1** 建立 Design Token：在 `apps/web/src/index.css` 用 Tailwind v4 的 `@theme` 定义色彩/字号/间距/圆角变量。统一色彩语言为：
  - `primary`（teal 系）：品牌主色，用于强调、激活态、主要 CTA
  - `neutral`（zinc 系）：文本、边框、背景
  - `semantic`：success-emerald / warning-amber / danger-rose / info-blue
  - `surface`：card / panel / overlay 三级表面色
- [ ] **B2** 引入 shadcn/ui 或自建基础组件库：Button / Card / Tabs / Dialog / Sheet / Popover / Toast / Tooltip / DropdownMenu / Command / Skeleton 等。所有页面逐步替换手搓 div + Tailwind 类名。需先 `npm i` 安装 `@radix-ui/react-*`、`class-variance-authority`、`cmdk` 等依赖
- [ ] **B3** 引入 framer-motion：页面切换、列表项进出、详情展开/收起、Tab 切换的过渡动画。需 `npm i framer-motion`
- [ ] **B4** 卡片层级化：定义 4 种卡片样式替代当前千篇一律的 `rounded-2xl border-zinc-200 bg-white`：
  - `primary-card`：主要内容卡，有阴影
  - `secondary-card`：次要内容卡，无边框有底色
  - `compact-card`：紧凑列表项卡，无圆角无边框
  - `data-card`：数据展示卡，带 metric label
- [ ] **B5** 字体系统：建立 `font-display`（标题）/ `font-body`（正文）/ `font-mono`（数据/代码）三级字体，明确字号阶梯（xs/sm/base/lg/xl/2xl/3xl）和行高

### 验收标准

- `index.css` 不再只有一行 `@import`，包含完整 `@theme` 定义
- 至少 8 个基础组件可复用（Button/Card/Tabs/Dialog/Sheet/Popover/Toast/Tooltip）
- 颜色 token 化，不再有 `zinc-200/teal-200/emerald-200` 等硬编码散落各页面
- `package.json` 新增 `@radix-ui/react-*`、`framer-motion`、`class-variance-authority` 等依赖

### 对照参考

当前 `index.css` 仅 1 行，`package.json` 无 shadcn/radix/headlessui/framer-motion 依赖

## 3. Phase C: 日报重构为结构化 Issue 形态（P0-P1）

**目标**：解决"日报太乱，不是想要的格式，效果没实现"的根因。当前日报本质是 AI 生成的 Markdown 长文，靠 `MarkdownContent` 渲染，没有结构化字段、没有视觉分层。

**预估工作量**：2-3 周

**依赖**：Phase B（要用设计系统和组件库）

### 子任务

- [ ] **C1** 日报数据结构化：后端从返回纯 Markdown 改为返回结构化 JSON，字段包含：
  ```typescript
  interface DailyReport {
    coverJudgement: string;        // 封面判断一句话
    editorNote: string;            // 编辑短评设定基调
    topicBlocks: Array<{           // 主题板块数组
      boldSummary: string;         // 粗体摘要句
      narrativeParagraph: string;  // 叙述段落
      citations: Array<{ user: string; url: string }>;  // 引用
      dataPoints: Array<{ label: string; value: string }>;  // 数据点
    }>;
    topItems: Array<{...}>;        // 重点条目卡片
    coverageIndex: Array<{...}>;   // 全池索引
    sourceDeclaration: {           // 数据来源声明
      checkedSources: number;
      totalItems: number;
      platforms: string[];
    };
  }
  ```
- [ ] **C2** Issue 化呈现：参考 AINews，每期日报有固定结构——封面判断（H1+Lead）→ 编辑短评（blockquote）→ 主题板块（粗体摘要句 + 叙述段落 + 引用链接 + 数据点）→ 重点条目卡片 → 全池索引 → 数据来源声明
- [ ] **C3** 工作台瘦身：把 Agent 矩阵、运行漏斗、监控数据移到独立的"诊断"tab，工作台首页只留"今日状态卡片 + 生成操作 + 高质量预览"3 个区域
- [ ] **C4** 阅读页右侧 sticky 边栏重构：改为"目录 + 跳转 + 元信息"，移除"运行漏斗/制作信息"等诊断内容（这些移到工作台诊断 tab）
- [ ] **C5** 主题板块视觉分层：每个主题板块用 `primary-card`，粗体摘要句作为卡片标题，叙述段落用 `font-body`，引用用 blockquote，数据点用 `font-mono` 高亮

### 验收标准

- 日报不再是单一 Markdown 渲染，而是结构化卡片组合
- 每期日报顶部有编辑短评设定基调（如"今天安静"）
- 主题板块有明确的视觉分层（粗体摘要 + 叙述 + 引用 + 数据）
- 工作台首页一屏可见内容不超过 3 个区域
- 阅读页右侧边栏不再有诊断内容

### 对照参考

AINews 的 Issue 结构（封面判断 → 编辑短评 → 主题板块 → Top tweets → Reddit 分组 → 数据来源声明）；AI HOT 的客观摘要与主观推荐用 `* * *` 分离

## 4. Phase D: Feed 信息流重构为多模式可切换（P1）

**目标**：解决"信息流展示问题很多"的根因。当前 `Feed page.tsx` 2404 行单个"上帝组件"，30+ useState，一屏同时承担阅读+配置+反馈+诊断。

**预估工作量**：3-4 周

**依赖**：Phase B（要用设计系统和组件库）

### 子任务

- [ ] **D1** 拆分上帝组件：`Feed page.tsx` 拆成 `FeedList` / `FeedDetail` / `FeedSourceRail` / `FeedToolbar` / `FeedReprocessPanel` / `FeedFeedbackPanel` / `FeedScoreBreakdown` 等独立组件，每个不超过 400 行
- [ ] **D2** 接入 react-query：替换 30+ useState，用 `useQuery` / `useMutation` 管理服务端状态。列表数据用 `useInfiniteQuery`，详情用 `useQuery`，反馈/重处理用 `useMutation`
- [ ] **D3** 卡片模式可选：参考 AI HOT 提供"高密度文本流"模式（单列、时间戳+来源+热度+标题+摘要+标签+多信源+推荐理由），参考 QMReader 提供"深度阅读"模式（多 tab + 中译/重写/划线/点评），用户在偏好切换
- [ ] **D4** 客观/主观分离：每条卡片区分"客观摘要"和"AI 推荐/编辑点评"，用视觉分隔（如 AI HOT 的 `* * *` 分隔线，或不同的背景色块）
- [ ] **D5** 多信源聚合前端呈现：复用已有的 `collapseEvents=true` 能力（EXT-013 已实现），前端把"多源印证"做成卡片内的可展开抽屉，区分本地来源/外部雷达/原始链接
- [ ] **D6** 虚拟列表：接入 `@tanstack/react-virtual`，列表流畅度支持上千条
- [ ] **D7** Feed 默认入口：根路径 `/` 从重定向到 `/insights` 改为重定向到 `/feed`（与 A2 联动）

### 验收标准

- `Feed page.tsx` 不再超过 400 行
- 状态变量从 30+ 降到 5 个以内（用 react-query 管理）
- 列表支持虚拟滚动，1000 条 60fps 不卡顿
- 提供"高密度文本流"和"深度阅读"两种卡片模式可切换
- 每条卡片明确区分客观摘要与 AI 推荐
- 多源印证可展开折叠

### 对照参考

- **AI HOT**：单列高密度文本流，每条 8+ 字段（时间/来源/热度分/标题/摘要/标签/多信源/推荐理由）
- **QMReader**：深度阅读 + 公开资产沉淀（中译/重写/划线/点评/对话）
- **AINews**：跨平台主题聚合，同一主题多视角呈现
- **Folo**：Discovery 排序与反馈、重度阅读效率（路线图已明确借鉴方向）

## 5. Phase E: 配置页面与诊断中心重构（P1）

**目标**：解决"配置页面干扰信息好多"的根因。当前 `Settings page.tsx` 3374 行，7 主 tab + 4 admin tab + 4 AI center tab = 15 个子区域全揉在一起。

**预估工作量**：2 周

**依赖**：Phase A（要先拆分路由）+ Phase B（要用设计系统和组件库）

### 子任务

- [ ] **E1** 用户偏好页重构（`/settings`）：只保留通用偏好 + 阅读 AI 偏好 + 集成 + 播客配额，移除管理员专属内容。每个 tab 内用 Section + Card 分组，避免 30+ 字段平铺
- [ ] **E2** 管理后台独立（`/admin`）：AI 管理中心（场景控制台/模型仓库/评分 Skills/使用日志）+ 诊断中心 + 用户管理 + 邀请码 + 系统任务，独立路由独立权限校验
- [ ] **E3** 配置项分组化：每个 tab 内用 Section + Card 分组，相关字段聚成一组，避免视觉混乱。例如"通用偏好"拆成"列表显示 / 自动刷新 / 链接打开 / 时间显示"4 个分组
- [ ] **E4** 诊断数据图表化：把"队列状态/抓取新鲜度/模型用量/评分健康"等诊断数据做成图表卡（折线/柱状/饼图），而非裸文本。引入 `recharts` 或 `visx`
- [ ] **E5** AI 配置场景化说明：每个 AI 场景（质检/评分/摘要/翻译/日报各 Agent）增加"为什么用这套模型"的运行说明，而非只有 prompt 编辑框
- [ ] **E6** Settings 文件拆分：3374 行拆成 `GeneralSettings` / `ReadingSettings` / `AiCenter` / `Integrations` / `Diagnostics` / `Quota` / `AdminDashboard` / `AdminTasks` / `AdminUsers` / `AdminInvites` 等独立组件

### 验收标准

- `/settings` 不超过 800 行，只含用户偏好
- `/admin` 独立路由，权限校验单独处理
- 诊断数据至少 4 个图表卡
- 每个 AI 场景有运行说明
- 用户能在 3 次点击内找到任何配置项

### 对照参考

Folo 的 Settings 信息架构组织；当前 13 个一级导航项无分组平铺是干扰来源

## 6. Phase F: 性能、可访问性与 PWA 化（P2）

**目标**：解决整体技术债——性能隐患、可访问性缺失、移动端适配粗糙。

**预估工作量**：1-2 周

**依赖**：Phase D（要先拆组件才能虚拟列表）

### 子任务

- [ ] **F1** 虚拟列表接入：Feed / 日报候选池 / 过滤池 / Sources 列表全部接入 `@tanstack/react-virtual`，支持上千条流畅滚动（与 D6 联动）
- [ ] **F2** 代码分割优化：路由级 lazy load（已做）+ 内部大组件按需加载（FeedDetail 的多 tab 内容、Settings 的各 tab 内容、日报的 CoverageIndexSection 等）
- [ ] **F3** 键盘导航支持：Feed 列表支持 `j/k` 上下条、回车打开详情、`esc` 关闭、`/` 聚焦搜索。日报阅读页支持 `j/k` 跳章节
- [ ] **F4** aria 完善与 WCAG 合规：所有交互组件补 aria 属性，focus 管理完整，键盘导航支持，对比度达 WCAG AA
- [ ] **F5** PWA 化：`manifest.json` + service worker（workbox），支持添加到主屏幕、离线缓存静态资源、弱网降级
- [ ] **F6** 移动端原生感增强：移动端底部 tab bar 替代当前侧边栏折叠；列表项支持 swipe 手势（标记已读/收藏/反馈）；详情页支持下滑关闭
- [ ] **F7** 性能监控：接入 `web-vitals`，监控 LCP/FID/CLS，超过阈值告警

### 验收标准

- Feed 1000 条滚动 60fps
- LCP < 2.5s，CLS < 0.1
- 全键盘可操作，无鼠标能完成核心流程
- 可添加到手机主屏幕，离线可打开
- 移动端有底部 tab bar 和 swipe 手势

### 对照参考

Folo 的重度阅读效率（键盘导航、手势操作）；当前移动端仅靠 Tailwind 断点

## 8. 风险与边界

### 8.1 风险

| 风险 | 缓解措施 |
|---|---|
| 重构期间破坏现有可用功能 | 每个子任务完成后跑 `make gate`；保持 `docs/36` 当前 111/115 完成项不回退 |
| 后端日报数据结构化（C1）涉及 API 契约变更 | 先保留 Markdown 兼容字段，新增结构化字段并行返回，前端逐步切换 |
| 引入 shadcn/ui 可能与现有 Tailwind v4 配置冲突 | shadcn/ui 已支持 Tailwind v4，按官方文档配置；先在隔离分支验证 |
| 6-8 周工作量与 36 号文件 EXT-021/022 时间窗冲突 | 前端重构不触碰后端契约，可与 EXT-021/022 shadow 观察并行 |

### 8.2 边界

- 不修改后端 API 契约（除 C1 日报结构化新增字段）
- 不修改数据库 schema
- 不修改 Docker / 部署架构
